# Task API (To-Do List API)

A RESTful API for managing tasks, built with **FastAPI** and **SQLite**.

---

## 1. Project Overview

Students and workers often lose track of what they need to do and by when.
This API gives any app (web, mobile, or script) a simple backend to store and
manage tasks. Each task has a title, description, due date, status, and priority.

**Primary resource:** `Task`

| Field         | Type   | Required | Notes                                  |
|---------------|--------|----------|----------------------------------------|
| `id`          | int    | auto     | Generated by the database              |
| `title`       | string | **yes**  | 1 to 100 characters, not blank         |
| `description` | string | no       | Up to 500 characters                   |
| `due_date`    | date   | no       | `YYYY-MM-DD`                           |
| `status`      | string | no       | `todo` (default), `in_progress`, `done`|
| `priority`    | string | no       | `low`, `medium` (default), `high`      |
| `created_at`  | string | auto     | Set by the database                    |

## 3. Setup Instructions

Requires **Python 3.10+**.

```bash
# 1. Clone the repository
git clone <your-repo-url>
cd task-api

# 2. (Recommended) create a virtual environment
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Run the server
uvicorn app.main:app --reload
```

The API runs at `http://127.0.0.1:8000`. The SQLite file `tasks.db` is created
automatically on first start.

**Interactive documentation (Swagger UI):** http://127.0.0.1:8000/docs
**ReDoc:** http://127.0.0.1:8000/redoc
**Raw OpenAPI JSON:** http://127.0.0.1:8000/openapi.json

**Run the tests**

```bash
pytest -v
```

## 4. API Reference (Technical Contract)

Base URL: `http://127.0.0.1:8000`

### Endpoint overview

| Method | URL                  | Description              | Success |
|--------|----------------------|--------------------------|---------|
| POST   | `/api/v1/tasks`      | Create a task            | 201     |
| GET    | `/api/v1/tasks`      | List tasks (filterable)  | 200     |
| GET    | `/api/v1/tasks/{id}` | Get one task             | 200     |
| PUT    | `/api/v1/tasks/{id}` | Replace/update a task    | 200     |
| DELETE | `/api/v1/tasks/{id}` | Delete a task            | 204     |
| GET    | `/health`            | Health check             | 200     |

### POST /api/v1/tasks

Request body:

```json
{
  "title": "Finish API project",
  "description": "Build, test and document it",
  "due_date": "2026-12-01",
  "status": "todo",
  "priority": "high"
}
```

Response `201 Created`:

```json
{
  "id": 1,
  "title": "Finish API project",
  "description": "Build, test and document it",
  "due_date": "2026-12-01",
  "status": "todo",
  "priority": "high",
  "created_at": "2026-11-26 03:48:00"
}
```

### GET /api/v1/tasks

Optional query parameters: `status` (`todo|in_progress|done`), `priority` (`low|medium|high`).
Example: `GET /api/v1/tasks?status=done&priority=high`

Response `200 OK`: a JSON array of task objects (empty array `[]` if none).

### GET /api/v1/tasks/{id}

Response `200 OK`: one task object (same shape as above).

### PUT /api/v1/tasks/{id}

Same body as POST (all fields are replaced; `title` is required).
Response `200 OK`: the updated task object.

### DELETE /api/v1/tasks/{id}

Response `204 No Content` (empty body).

### Error handling

All errors use the same JSON shape:

```json
{ "error": { "code": 404, "message": "Task with id 99 not found" } }
```

| Status | When it happens                              | Example message                                      |
|--------|----------------------------------------------|------------------------------------------------------|
| 400    | Invalid or missing data, bad id, bad filter  | `title: Field required`                              |
| 404    | Task id does not exist                       | `Task with id 99 not found`                          |

## 5. API Design Choices

- **Plural nouns, no verbs in URLs.** `/api/v1/tasks` names the resource; the HTTP method says the action (GET, POST, PUT, DELETE), never `/deleteTask`.
- **`/v1` in the URL.** Lets us release breaking changes as `/v2` later without breaking existing clients.
- **Meaningful status codes.** `201` for creation, `204` for deletion with no body, `400` for bad input, `404` for a missing task.
- **One error format.** Clients can always read `error.code` and `error.message`.
- **FastAPI.** Generates the OpenAPI/Swagger documentation automatically from the code, so docs and code never drift apart.
- **SQLite.** File-based and zero setup, so any developer can run the project in minutes.
- **Validation at the edge.** Pydantic models reject bad data (blank title, wrong status, invalid date) before it reaches the database.
